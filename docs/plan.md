# Plan and execution record

I split the 12-hour guide into six focused sessions: (1) model and authentication, (2) openings/applications CRUD, (3) pipeline and interview permissions, (4) search/bulk/export, (5) dashboard/alerts, and (6) tests, documentation, and deployment packaging. That ordering puts irreversible data rules before dashboard polish so every later view can rely on the same truth.

Estimated vs. intended allocation: data model and routes 3h, core UI 2h, permissions/pipeline 2h, reporting and alerts 2h, tests/docs/deployment 3h. I kept the interface intentionally plain and cut stretch ideas, custom design-system work, scheduling integration, and self-service candidate access. The highest-value proof is correctness: the server owns permissions, filtering, stage moves, and timeline writes.
